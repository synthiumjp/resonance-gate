# False-memory benchmark

One question: **how often does an agent memory hold or return something the user did not say (or that is no longer true)?**

Three systems, 72 synthetic scenarios, local models only, no network calls at run time.

| system | what it is |
|---|---|
| `sourcedrecall` | this repo's `server/sourcedrecall/profile_memory.py`: a deterministic parser (`rgx`, stanza dependency parse) writes facts with the user's own quote and date; no model call at ingest. `results/` holds the run at RG commit `36aea17` (sourcedrecall 0.3.4); the first run, at `03e0b24`, is kept in `results/raw_sourcedrecall_03e0b24.jsonl` (see Results by version). |
| `mem0` | Mem0 open source, `mem0ai==2.2.1`, fully local (below). |
| `rag` | Control with no extraction: every user message stored verbatim, top-3 by `BAAI/bge-small-en-v1.5` cosine. |

## What is in the test set

`cases.jsonl` (generated by `build_cases.py`): 72 scenarios, each one or two short dated conversations for one owner plus probe questions. All text is synthetic and was written for this benchmark; the sentences were not copied from `rgx/refusal_cases.py` or `docs/REVIEW_2026-09-05.md` (only the failure *types* were taken from them). No real conversation is used anywhere.

| class | n | what a correct memory does |
|---|---|---|
| a negation / non-assertion | 16 | denial, hedge, question, conditional, someone else's opinion: must not assert the positive |
| b stale | 12 | a fact replaced later: must not present the old value as current |
| c invention | 10 | never said: return nothing about it |
| d attribute absent | 10 | person known, attribute not: return nothing about the attribute |
| e assistant-injected | 12 | the assistant says something about the user and the user never confirms it: must not be stored as the user's fact |
| f control | 12 (16 probes) | plain true facts, must be returned |

23 scenarios are marked `split: "heldout"` (about 30%, stratified by class). The scenarios were all written before any system was run, and nothing was tuned to any system. Caveat: after the runs I read every returned line to audit the judge (below), including held-out ones, so "held-out" here means "not looked at while writing the cases", not a blind test set.

## How it is scored (`score.py`)

* **Control recall** (class f) is deterministic: a listed substring must appear in what the memory returned.
* **False memory** (classes a-e): fails if any returned line asserts the forbidden proposition. "Asserts" is decided by a local judge (`judge.py`): Ollama `qwen3:14b`, temperature 0, thinking off, one fixed short rubric, one returned line at a time, every call logged to `results/judge_log.jsonl`. A verbatim quote that only *mentions* the topic ("I'm not vegetarian" for "is vegetarian") must be judged NO. For classes a, b, e a line sharing no content word with the proposition or the question skips the judge (counted as not asserting); classes c and d send every line.
* **What counts as "returned"**: Mem0, `search(top_k=5)` result texts; RAG, the top-3 messages with their conversation date prefixed; sourcedrecall, `profile_recall` ranked facts (max 5) as `text [they said: "quote"]`, with `(no longer true)` prefixed where the system itself marks a fact as superseded. The `profile_context` block is scored as a second view (it came out identical to the recall view on this set).
* **Explicit abstention** (c+d): the system returned nothing. RAG always returns 3 messages by construction, so it scores 0 here; read it with "no false assertion", which only asks that nothing returned asserted the claim.
* Stale scenarios are judged per line. RAG and Mem0 return the old and the new fact together; a human or LLM reading both could choose the newer one, so the stale numbers measure "the old value is present as an unmarked current fact", which is what a consumer that trusts retrieved lines would see.
* Bootstrap: percentile 95% CI, resampling scenarios (cluster bootstrap), seed `20261002`, 10,000 resamples. Cells with 0 failures show `[0-0]`; with n=10-16 that is not a proof of zero rate (rule of three: upper bound about 3/n).

### Judge validation

`judge_items.jsonl`: 30 (proposition, line, label) items written by hand before any system output was seen (14 YES, 16 NO). `judge_validate.py` result (`results/judge_validation.json`): **29/30 = 96.7% agreement**, specificity on NO 16/16, recall on YES 13/14. The one miss is a labelling edge case ("is interested in learning Rust" vs "enjoys Rust").

On the real runs the judge was worse than on the validation set: reading all flagged lines (`audit_flags.py`) and all unflagged lines of Mem0 and sourcedrecall (`audit_unflagged.py`) found 9 false positives (class d, where "studying in Madrid" was read as stating the subject, etc.) and 1 false negative. `audit_overrides.json` records each correction with its exact line. Results are therefore reported twice: **A** as the judge produced them, **B** after the manual audit. Unflagged RAG lines were not audited line by line (they are the user's own words), and Mem0's borderline e07 line was left as the judge said.

## Exact configuration

* Mem0: `mem0ai 2.2.1` (+ `spacy 3.8.16` `en_core_web_sm`, `fastembed 0.8.1` for its BM25 leg, `qdrant-client 1.19.1`), telemetry off. LLM `qwen3:14b` temperature 0, via the derived Ollama model `qwen3-14b-fm` (`Modelfile.mem0`: identical weights, only `num_ctx 12288`). Embedder Ollama `nomic-embed-text` (768d), vector store on-disk local Qdrant. API: `add(messages, user_id=...)` once per conversation with both roles, `search(query, filters={"user_id":...}, top_k=5)`.
* **Two changes to how Mem0 runs, both needed to work at all**: (1) `num_ctx` 12288, because Mem0's extraction system prompt is about 8k tokens and Ollama's default 4096 context silently truncates it; (2) `think=False` passed to every Ollama chat call by wrapping `llm.client.chat` in the adapter, because Mem0 does not pass it and qwen3 would otherwise reason for minutes before the JSON. No Mem0 prompt was edited or replaced (`/no_think` was not needed). Mem0 2.x OSS rejects the `timestamp` argument, so the conversation dates reach Mem0 only through the text; its memories show it substituting the run date for relative times.
* Mem0 2.2.1 `add` is additive (extraction only; it does not update or delete older memories), which is why stale facts survive in it.
* RAG: `sentence-transformers 6.1.0`, `BAAI/bge-small-en-v1.5` with its query instruction.
* sourcedrecall: stanza 1.14.0, torch 2.13.0, python from `~/rg_private/halumem/official/.venv`; `RG_MEMORY_DIR` fresh per scenario; owner name `Jordan Pike` for all scenarios.
* Judge: Ollama 0.15.2, `qwen3:14b` (id `bdbd181c33f2`), temperature 0, seed 0, `num_predict 4`.
* Hardware: CPU only. The Ollama service on this machine has no working GPU backend (WSL, no ROCm/Vulkan build), so all LLM calls ran on a Ryzen 5 7600.

## Results by version (sourcedrecall only; Mem0 and RAG were run once)

Audited false-memory rate on classes a-e, control recall (f), and true-fact
side recall on a/b/e:

| sourcedrecall | all: false memory | all: stale (b) | all: control | all: side recall | held-out: false memory | held-out: control |
|---|---|---|---|---|---|---|
| `03e0b24` | 13% (8/60) | 67% (8/12) | 14/16 | 1/11 | 21% (4/19) | 5/7 |
| `36aea17` (0.3.4) | 7% (4/60) | 33% (4/12) | 14/16 | 6/11 | 16% (3/19) | 5/7 |
| Mem0 2.2.1 | 27% (16/60) | 100% (12/12) | 16/16 | 11/11 | 26% (5/19) | 7/7 |
| RAG | 20% (12/60) | 100% (12/12) | 16/16 | 11/11 | 21% (4/19) | 7/7 |

Between the two runs, sourcedrecall was changed using this benchmark's dev
cases: parsing of subjectless and past-tense fragments ("Sold the Corolla on
Saturday"), "They promoted me to ...", names introduced with a relation ("my
dog Biscuit"), more state families (home, diet, role), endings matched past
time words and plurals, and questions about a state answered by a fact in
that state's family. So the dev numbers for `36aea17` are not an unbiased
estimate. The held-out split is the better guide, and it moved little (one
stale case). The four held-out stale cases were read before those changes,
so they are not blind for `36aea17` either. A fresh set of cases is needed
to measure the change properly.

## Reading the results (what the numbers do and do not say)

* Class a (denials, hedges, questions, conditionals, reported opinions): no system returned an asserting line, including sourcedrecall at `03e0b24`. This class does not separate the systems on this set.
* Class b (stale) dominates every system's false-memory rate. At `03e0b24` none of the systems marked an old value as replaced in this set: Mem0 2.2.1 never deletes, RAG returns both messages, and sourcedrecall did not parse the replacing sentences ("relocated to Coburg", "dropped the Italian class", "split up"), so its old fact stayed unmarked. Its 4 "passes" in class b are cases where it extracted nothing at all (empty return), not cases where it resolved the conflict; its true-fact side recall of 1/11 shows this.
* Class e: Mem0 stored assistant statements about the user as user facts in 4 of 12 scenarios (vegan, shellfish allergy, Seattle, and the borderline Go case); RAG cannot, because it stores user messages only (a property of the control, not a skill).
* At `36aea17` sourcedrecall marks 8 of the 12 changes and returns the new value first; the 4 it misses need knowledge it does not have (that Anytime Fitness is a gym) or are held-out cases it does not parse.
* sourcedrecall's price is recall: control recall 14/16 (it returned nothing for the marine-biology control f06 and for one of the three f12 probes), and it dropped the freight-job fact in a05.
* Cost: sourcedrecall 0 model calls and about 0.12 s per message; Mem0 about 1.6 model calls and 24 s per message on CPU (168 calls for 108 messages).

## Limitations

* 72 scenarios, one or two probes each, one short conversation each; CIs are wide, and held-out cells (n of 3-7 for most classes) are mostly uninformative.
* Authored by the people who build one of the three systems, with failure classes taken from that system's own test history. The classes were chosen because they are where extraction goes wrong; they say little about everyday recall.
* The judge is a 14B model; its errors were audited by one person (the author). Stricter or looser audits would move individual cells by a few probes.
* The fact-extraction class a-e design favours "returns nothing" (an empty memory cannot assert a falsehood). That is why control recall and true-fact side recall are reported next to false-memory rate, and why a system that stores nothing is visible in them.
* Mem0 was configured by the benchmark author with a local 14B model; a hosted-model Mem0 would extract differently.
* Latency figures are single runs on a loaded CPU box; Mem0's include a cold model load for the first scenario.
