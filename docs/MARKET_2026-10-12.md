# Users, competitors and research: where sourcedrecall stands (2026-10-12)

Three web-research passes by sonnet agents on 2026-10-12: what users say
about AI memory, the competing systems, and research from 2025-2026. They
worked from Hacker News, vendor pages, comparison sites, arXiv abstracts
and one audit blog; Reddit was not reached, few pages were read in full,
star counts differ by up to 2x between sources, and many of the papers are
preprints read from their abstracts. Treat each item as a lead to check
before it is quoted anywhere public.

## What users want and do not want

Ranked by how often it came up (Hacker News 2025-12 to 2026-09, GitHub
issues, one press test):

1. Stale or wrong memories that mislead the model. Claude Code's own
   memory "occasionally useful but much more often harmful" (HN 48777419);
   users turning auto-memory off over outdated memories (HN 49391724); a
   ZDNet test of ChatGPT memory where outdated details shaped later answers.
2. Invented or rewritten memories. mem0 issue #3322: a coworker's
   credential was rewritten into "has a PhD" about the user; the
   maintainer said inference is intended and added `infer=False`. A user's
   audit (secondhand) found most of 10,134 mem0 entries junk.
3. A black box: people cannot see, edit or forget what is stored.
4. Context bloat: "blanket memory doesn't scale"; every recalled memory
   costs tokens.
5. Turning memory off: stale facts, contaminated context, no control,
   reproducibility.
6. Privacy and cost: objections to cloud calls, API keys and recurring
   embedding costs; memory tied to one vendor's folder.
7. Jobs wanted: project context and decisions across coding sessions,
   preferences across projects, one memory shared by Claude Code, Codex
   and Cursor, search over old transcripts.
8. Proof: "we really need benchmarks"; run a fixed task with and without
   memory, separating fewer tokens from better results.

Weak evidence: how much people value provenance as such, and demand for
offline use beyond objections to cloud calls.

## The competition

| | LLM at write time | local | price | headline numbers |
|---|---|---|---|---|
| mem0 / OpenMemory (~60K stars) | yes | both | open source; cloud $19-249 | LoCoMo 92.5, LongMemEval 94.4 (own managed platform, own judge) |
| Zep / Graphiti | yes (graph) | Graphiti self-host; Zep cloud | from ~$104/mo | LongMemEval 71.2 (2025); now claims 94.7 LoCoMo |
| Letta | the agent edits its memory | both | open source; cloud $20/mo | none clear |
| Supermemory, Cognee, MemOS, memU, LangMem, Memobase | yes | mixed | mixed | self-reported |
| MemPalace (~50K stars) | no | yes | free | LongMemEval retrieval 96.6% (recall, not answers) |
| agentmemory | no | yes | free | LongMemEval retrieval R@5 95.2% |
| Basic Memory, official MCP memory server | no (the client writes) | yes | free | none |
| Claude Code auto memory (Feb 2026), ChatGPT, Gemini | yes | Claude Code local files; others cloud | bundled | none |

Crowded: memory layers that call a language model to extract facts, with a
hosted tier; and small local MCP memory servers. The default our users
already have is Claude Code's own memory.

No competitor found decides with a parser what is current or out of date,
marks pasted text as someone else's, or reports false-memory rates. Zep's
time-aware graph is the nearest on out-of-date facts and needs a language
model. Not verified against every README.

Benchmark claims do not compare. Vendor LoCoMo scores above 90 are
self-reported on their own model, judge and setup; third-party tests put
Zep near 75; mem0's best numbers are its managed platform, not the open
source library. An audit (Penfield Labs, 2026-04-08) found 6.4% of
LoCoMo's answer key wrong and a gpt-4o-mini judge accepting 62.8% of
deliberately wrong, on-topic answers. MemPalace and agentmemory report
retrieval recall, not answer accuracy.

## Research, 2025-2026

- Out-of-date facts are the weak spot. Embedding similarity barely tells a
  stale fact from its replacement (MemStrata, arXiv 2606.26511, AUROC
  0.59); a deterministic rule with no language model cut stale answers
  from 15-40% to about 0%. On a fact-update test mem0 scored 18% and Zep
  7%, BM25 48% ("Don't Ask the LLM to Track Freshness", 2606.01435).
  Implied changes (STALE, 2605.06527) and consequences of a change (RECON,
  2607.16716) remain unsolved.
- Raw messages with good retrieval are a strong baseline; extraction by a
  language model drifts from what was said (MemMachine 2604.04853,
  HaluMem 2511.03506). Long-context models beat fact-extraction memory on
  recall up to their window (2603.04814); memory pays on cost, and fails
  less at million-token histories (BEAM, ICLR 2026).
- Memory poisoning is an OWASP 2026 risk (ASI06). Attacks inject through
  ordinary queries (MINJA 2503.03704) or stored "experiences"
  (MemoryGraft 2512.16962); the emerging defence caps trust by where
  content came from (2606.22030), which is what marking pasted text does.
- Provenance: "provenance-role collapse" in flat-text memory (MemIR
  2605.25869); surveys argue for recording source and time at write
  time. No paper found using dependency parsing, presupposition,
  change-of-state verbs, reported speech or hedges for agent memory.
- Benchmarks: LongMemEval (ICLR 2025), MemoryAgentBench and BEAM (ICLR
  2026), HaluMem (stage-wise: extraction, update, answer), MemoryArena
  (systems that saturate LoCoMo do poorly on agent tasks).

## Where sourcedrecall stands against this

| what users or research ask for | sourcedrecall now |
|---|---|
| out-of-date facts handled | dated messages first; "no longer true" and "may have changed since" from the parser. Weak on changes only implied (held out v5: labels on 2 of 25) |
| your words, not a rewrite | answers come from the user's own dated messages; notes are optional and labelled |
| someone else's text kept apart | pasted text marked with its writer; held out v10: 3 of 40 pasted claims given as the user's (plain retrieval 23, agentmemory 20) |
| no language model, local, free | parser on CPU, no model call to store, Apache-2.0, ~0.9 GB |
| see, edit, forget | MEMORY.md, a read-only browser, forget by id; forget's gaps listed in the review (3.4) |
| one memory across tools | Claude Code, Codex CLI, Gemini CLI, Cursor, MCP; ChatGPT and Claude.ai imports |
| small, on demand | a block per question (LoCoMo mean ~1,000 tokens) |
| works with any model | two reader families on development data; v11 tests it held out |
| proof with and without memory on real tasks | missing: no task-level harness |

## What to do

1. Lead the README and launch with what no one else measures: false
   memories, pasted text, out-of-date facts, no model call to store. Say
   which mem0 was measured (the open-source library, local Qwen3-14B).
2. Add MemPalace and Claude Code's own memory to the false-memory
   comparisons (after the v11 run).
3. Build a with-and-without-memory task harness for coding sessions:
   pass rate and tokens.
4. Report stage-wise numbers (what was stored, what was marked out of
   date) as well as answers, as HaluMem does.
5. Present pasted-text marking as a defence against memory poisoning too.
6. Implied changes are the research's open problem and ours: the next
   parser work.
7. The linguistic approach has no published counterpart: a paper is
   possible.
