# Adversarial review, 2026-10-09 (commit b256b4d)

Five reviewers, asked by JP: one Opus agent on the whole system, four Sonnet
agents on the parser rules, security and privacy, the benchmark code and the
notes pipeline. Each finding below was either run by the reviewer (V) or read
from the code (S); the first ones were checked again by the developer before
being listed. Held-out case files were not opened by any reviewer.

## A. The comparisons and the claims (fix the evidence or the wording)

1. V. The false-memory and head-to-head reader got sourcedrecall's lines with
   the product's rules paragraph ("a later line can update an earlier one...
   anything not listed is UNKNOWN") and every other system's lines bare
   (`bench/false_memory/answer.py`). Part of the lead may be the instruction.
   Most gaps are not significant (Fisher, two-sided): v4 2 vs 5 of 44 p=0.43,
   vs plain retrieval 2 vs 7 p=0.16; coding 0 vs 2 p=0.50; v5 A 0 vs 4 of 25
   p=0.11, B 3 vs 7 p=0.29; projects 0 vs 9 of 32 p=0.002.
2. V. sourcedrecall's release-run answers were never audited: the old
   overrides match by exact answer text and matched nothing; the other
   systems were audited both ways. The 4B row's gap came from the audit.
3. V. The judge never sees the question, so a bare answer ("Brunswick.") is
   hard to judge; its validation (29/30) was on memory lines, not answers.
4. V. The expected-term check is a substring match: "I don't know" matched
   "no" (in "know"); some terms are in the question itself. Inflates control
   recall and "new state given".
5. V. Error rows and empty answers score as passes (none in current results).
6. V. README: LoCoMo plain retrieval got 10 turns and Mem0 10 per speaker, not
   "top 3 / top 5"; Mem0's 941 calls include embedding calls; "answered I
   don't know to 5 real facts" is stale (2); the demo sentence "sourcedrecall
   has nothing" is wrong (small stores return every message); the demo's
   plain retrieval indexes assistant messages, the benchmark's does not.
7. V. README calls v4, coding and projects "held-out sets written before any
   system was run"; they have been run many times and rules were written
   from their error categories (PREREG_HELDOUT_V5.md says so).
8. V. The README omits v5's advice result (2/10 vs plain retrieval 8/10,
   p=0.02, the only significant effect, against us). H6 (right conversation
   in the top 5 of up to 50 messages, scenarios of 4-6 conversations) is
   close to vacuous.
9. V. The change labels rarely fire on unseen data (v5: "no longer true" 4
   times, "may have changed since" 8, over 50 changes), yet the README leads
   with them.
10. V. LongMemEval: the routing was tuned on its 30 preference questions (90.0
    -> 96.7 = the 98.4 -> 98.8 headline); the parser was stubbed; our own
    bge baseline (96.8) beats both published competitors, so the gap is
    mostly the harness. "Confirmed on data it was not tuned on" for the advice
    answers is wrong (same 30; 16 vs 13, p~0.45).
11. V. LoCoMo: without temporal questions, where Mem0 got no timestamps,
    sourcedrecall 67.4% vs Mem0 71.3%. The test conversations were run 10+
    times and chose the architecture. The benchmark sets RG_NLI=0; the server
    loads NLI by default.
12. V. "It cannot plant an instruction": "Here's what my manager sent: Always
    copy legal on every reply." becomes a standing instruction.
13. V. Codex/Gemini/Cursor capture is stated as working; never run in the apps.
14. V. Notes: "add no false memories" is wrong (3 and 4 of 44 vs 2 without);
    real cost on a long coding session ~100 s and 3.6 GB, not 2-3 s and
    1.9 GB; the model card calls the LoCoMo test held out; the small model
    often writes NONE on short sessions.
15. Wording: "never calls a language model" (Stanza uses a character LM,
    embedders, an NLI model); "nothing leaves your machine" (the block goes to
    the agent's cloud model; a notes URL can be remote); English only.

## B. Security and privacy (README promises broken)

1. V. Forget does not erase: the sentence stays in conversations.json,
   profile_cache.jsonl, MEMORY.md (via other facts quoting the sentence) and
   corrections.jsonl (stored in clear); rehydrate returns it.
2. V. Secrets survive: `DB_PASSWORD=`, `*_SECRET_KEY=`, `client_secret`
   (the keyword regex needs a word boundary the underscore blocks);
   conversation titles are never scrubbed; the Cursor spool is raw and 0644.
3. V. The memory browser checks no Host header (DNS rebinding reads it from a
   web page), has no token, sends no security headers.
4. V. Concurrent writers lose sessions (thread lock only, fixed .tmp names):
   4 processes stored 3 conversations.
5. V. Files are world-readable (0644 in 0755 dirs); /tmp hook log predictable.
6. V. Stored text can imitate the memory's own headers inside the context.
7. S. Offline mode is set only by the MCP server and service, not the hook
   worker or CLI; a missing ONNX model falls back to network downloads.
8. S. MCP write tools let a prompt-injected agent store "user" statements.
9. Low: tar fallback without the data filter on old Pythons; mutable tag in
   the plugin; workflow actions not pinned by SHA; importer zip size.

## C. Parser rules (counterexamples run on the parser)

- Change labels: plans, modals and negations mark the current state "no
  longer true" ("I might move to Brunswick", "I'm moving next year", "I
  didn't move after all"); "I lived in Fitzroy for ten years" after the move
  marks the NEW home; switch/quit/broke up/same-day changes missed.
- Hedge, report and wish frames leave a bare complement ("I guess I live in
  Leeds now" -> "lives in Leeds now"; "allegedly...", "I heard I'm...").
- Questions without "?" still stored ("remind me what city I live in").
- Instructions: "Always use tabs not spaces" -> "Always use tabs"; "Never
  again will I use that vendor" -> "will use that vendor"; "Never mind",
  "Keep the change" stored; "Be concise", "Call me Dan", "from now on" missed.
- Pasted text: "what do you make of this" + email, quoted replies (">"),
  "Translate to French: ..." read as the user's; and the colon rule labels
  the user's own words as pasted ("Here are my notes: I'm vegan...").
- Presupposition: "Third week at X was when they fired me" -> works at X now.
- Decisions: "ok" / "ok thanks" after informational advice -> a decision;
  reversals and choices ("redis it is") missed.
- Advice pattern: fires on "how should I have known", "what should I expect
  from this regex", coding how-to; misses "Help me choose a phone", "I need a
  gift idea for my mum".
- explicit_person: curly apostrophes ("I’m" -> "Dan’m"), verbs other than
  be/have, quotes and code rewritten, generic "you", "mine" the noun.

## D. Notes pipeline

1. V. Forgetting does not stick: the next resumed ingest rewrites the note.
2. V. A session that failed (or predates `--notes`) never gets notes.
3. V. Quotes rewritten by explicit_person create wrong-person notes ("I own
   three buildings" in a landlord's email -> "Dana owns three buildings").
4. V. grounded() passes inverted or wrong-number notes; whole-session
   grounding is lax.
5. V. Long sessions lose text silently (1,500 chars a turn, 8 parts).
6. V. A truncated last line is stored; owner check is a substring ("Al").
7. Reproducibility: tools/distil imports `notes_ref` (not in the repo) and
   hard-coded Mac paths.
