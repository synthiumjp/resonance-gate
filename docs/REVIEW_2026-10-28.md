## Code

C1 (critical, verified, fixed c641cdd). With RG_TRIM_LONG (default since
8d14d39), a message over 800 characters kept a note only if the fact's
text appeared in the quote. The user's own facts are stored in the third
person ("Dana Cole works at ..."), so every note about them in a long
message was dropped, and its replacing message was not pulled in. Now
matched on the fact's source sentence. Test:
test_memory_api.py::test_a_long_message_keeps_the_note_on_the_users_own_fact
(fails on the old code). Dev recheck: dev28.

H4 (high, verified, fixed c641cdd). mark_frame_changes linked
many-valued subjects ("Christopher Nolan directed Inception", later
"... Oppenheimer"; "studied at"; "allergic to" a year apart). Verbs whose
subject holds many values now count only in the passive ("Inception was
directed by ___") or with a slot noun ("plays the position of ___");
slots like "allergic to", "fluent in", "a fan of" never. Precision on
real conversations is still unmeasured (open).

M4 (fixed c641cdd). RG_NOTE_LATER's text is made inert like other notes.

Open, code: H5 MCP write tools (profile_ingest can write as the user with
a backdated date; forget/correct not marked destructive; no undo or
audit log). H6 pasted rules can become standing instructions when the
paste's introduction does not end in ":" or "?". M1 _trim_best falls back
to the first 240 characters when no sentence shares a word (own2 -1).
M2 death guard reads the whole sentence, not the clause. M3 _tail and
_name_slot edge cases (abbreviations, sentence openers, non-ASCII names).
M7 install not reproducible (no lock, unpinned WordNet). M8 secrets
filter gaps. Low: lock fails open, _erase_spools outside the lock, Cursor
worker on every stop, whitespace owner split.
